# Uno.AdMob Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Plugin.AdMob v11.0.0.0 to an Uno Platform 7.0 library `MZikmund.Uno.AdMob` (banner, interstitial, rewarded, rewarded interstitial, app open, UMP consent) that is cheap to re-sync with upstream.

**Architecture:** Mirror port. Upstream `src/Plugin.AdMob/**` is copied into `src/Uno.AdMob/**` at the same relative paths with the root namespace `Plugin.AdMob` → `Uno.AdMob`, and only MAUI-specific code is replaced, each spot marked with a short `// Uno:` comment. A minimal internal `ViewHandler<TView, TPlatformView>` base class lets upstream's banner handler bodies compile almost unchanged under a WinUI `ContentControl`. Upstream's own `#if !ANDROID && !IOS` fallback serves the `net10.0` and Windows targets.

**Tech Stack:** Uno.Sdk 7.0.22, .NET SDK 10.0.400, `Xamarin.Google.Android.Libraries.Ads.Mobile.Sdk` 1.5.0, `Xamarin.AndroidX.Fragment.Ktx` 1.9.1, `Jc.GMA.iOS` 12.10.0, `Jc.UMP.iOS` 2.7.5, MSTest 4.3.2, Nerdbank.GitVersioning 3.10.94.

**Spec:** `docs/superpowers/specs/2026-11-18-uno-admob-design.md`

## Deviations from the spec (decided while planning)

- The static entry point is **`AdMobPlatform`** (`AdMobPlatform.IsSupported`, `AdMobPlatform.Initialize(IServiceProvider)`), not `AdMob`. A class named `AdMob` inside namespace `Uno.AdMob` causes name-resolution clashes.
- `AddAdMob` lives in the upstream class/file `Config` (`Config.cs`) rather than a new `AdMobExtensions`, to keep the file diffable.
- `UnsupportedPlatform.PostLoadFailure` uses `SynchronizationContext.Current?.Post(...)` instead of `DispatcherQueue`. This posts to the UI thread on every Uno head and also works in unit tests (no WinUI runtime needed).

## Review Focus

1. **Event raised before the caller subscribes** – on fallback, `Load()` must not raise `OnAdFailedToLoad` synchronously when a `SynchronizationContext` exists. Pinned by `UnsupportedPlatformTests.Load_WithSyncContext_PostsFailure` (Task 2).
2. **Shared XAML on desktop/Windows** – a `BannerAd` in a page must not crash or take space on unsupported heads. Pinned by the Task 6 sample's desktop head (runs, banner invisible) and by `BannerAd_Fallback` checks in Task 4.
3. **Using a `BannerAd` or service before `AdMobPlatform.Initialize`** on Android/iOS – must fail with a clear `InvalidOperationException` message, not a NullReferenceException. Pinned by `AdMobPlatformTests.GetRequiredService_BeforeInitialize_Throws` (Task 2); handlers resolve services only through that method.
4. **`IMobileAdsService.Initialization` never completes on unsupported platforms** (upstream behaviour, kept for parity). Awaiting it on desktop hangs. Documented in the README "Unsupported platforms" section (Task 6) and pinned by `MobileAdsService_Fallback_InitializationNeverCompletes` (Task 2).
5. **Consent flow when `Initialize` runs after the first activity/scene is already active** – the automatic consent form must still appear. Pinned by the Task 4/5 manual sample check ("consent form shows on cold start in EEA debug geography").
